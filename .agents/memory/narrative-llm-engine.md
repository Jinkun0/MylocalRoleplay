## Decision

Narrative prose (player-facing dialogue/action responses, and world-tick summaries) is generated by an LLM (Anthropic Claude, via Replit AI Integrations — no user-provided API key), not by template banks. The action-response call uses forced tool-use (`tool_choice: {type:"tool", name:...}`) so the model returns structured fields (narrative text, relationship deltas, memory-worthiness, movement target, world-event worthiness) alongside the prose, instead of freeform text that would need brittle parsing.

**Why:** The user explicitly chose this over a procedural/template system, prioritizing long-term coherence, immersion, and avoiding repetitive/generic responses — the game should feel like a living world, not a chatbot. Templates were the Phase-1 placeholder and were replaced wholesale once Phase 2 (NPC realism) and Phase 3 (tone/prose quality) began.

**How to apply:** Any new narrative-generation touchpoint (new action types, new world systems) should extend the existing structured tool schema rather than reintroducing template strings. Keep world-simulation (deterministic state changes — NPC movement, routines, clock) separate from narrative-generation (LLM prose) — only the latter should call the LLM.
